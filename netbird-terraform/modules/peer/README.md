# NetBird Peer Module

Manages server-side configuration, access governance, and metadata for existing NetBird peers (`netbird_peer`).

## Architecture
- **Type**: Collection (`var.items`)
- **Resource**: `netbird_peer`
- **Data Source**: `data "netbird_peer"` (optional dynamic lookup)

> [!IMPORTANT]
> **Terraform does NOT register new peer agents from scratch.**
> A NetBird peer represents a physical or virtual machine running the NetBird agent daemon (`netbird up`). The peer must first register via a Setup Key or interactive user SSO.
> This module manages server-side governance (name, SSH access, approvals, expiration) for **already-registered peers**.

---

## Why the Resource Schema Looks "Incomplete"

When viewing the [official Terraform Registry documentation for netbird_peer](https://registry.terraform.io/providers/netbirdio/netbird/latest/docs/resources/peer), the schema lists 25 attributes. However, **only 6 are configurable arguments**:

| Attribute | Type | Mode | Description |
| :--- | :--- | :---: | :--- |
| `id` | `string` | **Required** | The unique Peer ID (can be resolved dynamically) |
| `name` | `string` | Optional | Custom display name / hostname override |
| `ssh_enabled` | `bool` | Optional | Enable built-in NetBird SSH server on this peer |
| `approval_required` | `bool` | Optional | Enforce admin approval before peer joins network |
| `inactivity_expiration_enabled` | `bool` | Optional | Enable session expiration on inactivity |
| `login_expiration_enabled` | `bool` | Optional | Enforce re-authentication on login expiration |

### The Other 19 Attributes are Read-Only (Computed)
All other attributes reported by the NetBird API (`ip`, `hostname`, `dns_label`, `extra_dns_labels`, `connected`, `connection_ip`, `country_code`, `city_name`, `geoname_id`, `groups`, `os`, `version`, `ui_version`, `kernel_version`, `serial_number`, `user_id`, `last_login`, `last_seen`, `login_expired`) are **device telemetry properties** generated by the agent or NetBird IPAM engine. They cannot be written to by Terraform, but are automatically exported in `output.peer_metadata`.

## How to Fetch the Peer ID

You can obtain the Peer ID through 4 different methods:

### Method 1: Automatic Dynamic Lookup via Terraform (Recommended)
You do **not** need to hardcode the `id`. You can specify either `name` or `lookup_ip` in `items`:

```hcl
module "peers" {
  source = "../../modules/peer"

  items = {
    # Resolved dynamically by peer name
    "bastion" = {
      name        = "bastion-dev"
      ssh_enabled = true
    }

    # Resolved dynamically by WireGuard IP
    "k8s_node" = {
      lookup_ip   = "100.64.0.15"
      ssh_enabled = false
    }

    # Explicit ID (skips dynamic lookup)
    "database" = {
      id          = "ch49k28d9s01hfa23k80"
      ssh_enabled = true
    }
  }
}
```

### Method 2: NetBird Management API (`curl`)
List all registered peers and their IDs:

```bash
curl -s -H "Authorization: Token ${NB_PAT}" https://netbird.REPLACE_ME_DOMAIN/api/peers \
  | jq -r '.[] | {id: .id, name: .name, ip: .ip, hostname: .hostname}'
```

To extract the ID of a specific peer by name:

```bash
curl -s -H "Authorization: Token ${NB_PAT}" https://netbird.REPLACE_ME_DOMAIN/api/peers \
  | jq -r '.[] | select(.name == "bastion-dev" or .hostname == "bastion-dev") | .id'
```

### Method 3: From the Client Machine (`netbird status`)
On the machine running the NetBird agent:

```bash
netbird status --detail
```

The output displays the **Management Peer ID**, WireGuard IP (`100.64.x.x`), and connection status.

### Method 4: NetBird Web Dashboard
1. Open the NetBird Dashboard &rarr; navigate to **Peers**.
2. Click on the target peer.
3. The peer detail panel displays the **Peer ID** with a copy button.

## Inputs

| Name | Type | Description | Default |
|------|------|-------------|---------|
| `items` | `map(object)` | Map of peer management configurations | `{}` |

### Item Attributes

- `id` (`string`, optional if `name` or `lookup_ip` is provided): Existing NetBird peer ID.
- `name` (`string`, optional): Peer display name (also used for lookup if `id` is null).
- `lookup_name` (`string`, optional): Explicit name to use for data source lookup.
- `lookup_ip` (`string`, optional): WireGuard IP (`100.64.x.x`) to use for data source lookup.
- `ssh_enabled` (`bool`, optional): Enable NetBird SSH access to this peer.
- `approval_required` (`bool`, optional): Require admin approval before joining.
- `inactivity_expiration_enabled` (`bool`, optional): Enable session expiration on inactivity.
- `login_expiration_enabled` (`bool`, optional): Enable login expiration.

## Outputs

| Name | Description |
|------|-------------|
| `peer_ids` | Map of peer keys to peer IDs |
| `name_to_id` | Map of peer names to peer IDs |
| `peer_ips` | Map of peer keys to assigned WireGuard IPs |
| `peer_metadata` | Comprehensive map of computed telemetry (`ip`, `hostname`, `dns_label`, `connected`, `os`, `groups`, etc.) |
